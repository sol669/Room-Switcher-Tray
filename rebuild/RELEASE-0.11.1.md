# RoomSwitcher 0.11.1 — тестовое исправление

## Исправлено

- Устранён конфликт чтения аудиоустройств и подписки на их изменения. В 0.11.0 два управляемых класса описывали один COM-класс Windows, что приводило к InvalidCastException при запуске наблюдателя раньше чтения списка.
- Определения Core Audio вынесены в общий слой. Каждый владелец получает отдельную COM-обёртку; временное чтение больше не освобождает обёртку долгоживущего наблюдателя. Для возвращаемых интерфейсов освобождается только полученная ссылка, без принудительного обнуления ссылок других читателей.
- В обычном меню трея показываются только экраны и аудиоустройство активного сценария. Устройства других сценариев, дополнительные активные мониторы и резервный аудиовыход Windows не добавляются.
- Неподключённое устройство сценария остаётся в списке. Например: «Звуковая карта — Не подключён». Сбой чтения отображается отдельно как «Нет данных», а отключение в Windows — «Отключено в Windows».
- Команда выключения звука привязана к конкретному аудиовыходу строки, а не к текущему выходу Windows на момент нажатия. При исчезновении устройства команда не затрагивает резервный выход.

## Сохранено

- Для переключения достаточно одного доступного экрана сценария; отсутствие или ошибка аудио не блокирует видео.
- Сохранённые привязки и имена не сбрасываются. Раздел «Имена устройств» остаётся общим каталогом.
- Предупреждение о частичном применении, событийное обновление, ограниченное ожидание HDMI и отдельный режим RDP остаются. Режим RDP по-прежнему отделён от локальных сценариев.
- Настройки не включаются в архив обновления и не заменяются им.

## Выполненные проверки

- На коде 0.11.0 новым тестом воспроизведена исходная InvalidCastException при порядке «наблюдатель → чтение».
- 69 проверок политики сценариев и состояния, включая отсутствующий звук, ошибку чтения аудио, отсутствие резервного выхода в трее и отсутствие устройств других сценариев.
- Реальный Core Audio, без изменения конфигурации: три отдельных процесса с порядками «наблюдатель первым», «читатель первым», «сторонний COM-класс первым»; суммарно 316 чтений, STA и четыре параллельных MTA-потока, перекрытие времени жизни наблюдателей, проверка независимости обёрток.
- На опубликованной сборке: 52 чтения при работающем наблюдателе, 30 аудиоэндпоинтов, основной выход PC (Audient iD14); 20 вложенных регистраций/отписок. Дескрипторы тестового процесса до/после 10 секунд ожидания: 626/626. Это не замер потребления полного приложения.
- Сборка Release x64, проверки ресурсов и версии, 224 отрисовки иконок сценариев, 6 образцов литер, 24 отрисовки состояния, 9 размеров основной иконки и проверки оформления настроек.
- Получение сведений об уязвимостях NuGet недоступно в локальном окружении (NU1900); компиляция завершена успешно, зависимости не изменялись.

## Что проверить вручную перед релизом

1. После обновления в «Именах устройств» есть реальные системные названия аудиовыходов.
2. В «Кабинете» только его экраны и звуковая карта; экран и звук телевизора не попадают сюда из «Гостиной».
3. При отключённой аудиокарте её строка остаётся, резервный выход Windows не появляется; переключение сценария не блокируется.
4. При отключении одного из двух экранов сценарий работает на оставшемся, недостающий экран отмечается.
5. Переключение на телевизор, HDMI-звук, быстрое переключение обратно и поведение в RDP.

Приложение при подготовке не запускалось. Физические устройства не отключались, настройки и звук не переключались. Доставка реальных уведомлений при hot-plug и визуальное поведение окна требуют ручной проверки. Релиз на GitHub не опубликован.

Техническое основание владения COM-обёртками: [Microsoft — GetUniqueObjectForIUnknown](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.marshal.getuniqueobjectforiunknown).
